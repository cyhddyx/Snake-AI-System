# Snake-AI-System 答辩版 README

蛇类图鉴与智能识别系统是一个面向蛇类科普、物种检索、图像识别、智能问答和用户内容共建的综合应用。项目采用前后端分离架构，前端负责页面交互与业务流程组织，主后端负责用户、物种、收藏、投稿审核和 AI 问答接口，识别服务负责基于 BioCLIP 2 的蛇类图像分类，图片服务负责本地图片上传与访问。

这份文档偏向答辩讲解，重点说明“系统做了什么、为什么这样设计、每个模块怎么配合、老师问到时该怎么回答”。

## 一、项目定位

本项目解决的是“普通用户缺少系统化蛇类知识入口”和“蛇类图片识别、百科查询、内容维护分散”的问题。系统把蛇类知识库、图像识别模型、智能问答和用户投稿流程整合在一起，形成一个从查询、识别、收藏到补充数据的完整闭环。

可以在答辩中这样概括：

> 本系统不是单纯的网页图鉴，而是一个围绕蛇类知识管理构建的前后端分离平台。它既支持传统的分类检索和物种详情浏览，也接入了 BioCLIP 2 图像识别和 DeepSeek 智能问答，并且通过投稿审核机制支持后续知识库持续扩展。

## 二、核心功能

### 1. 蛇类图鉴

- 展示蛇类物种列表。
- 支持按科、属、毒性、IUCN 状态等条件筛选。
- 支持中文名、拉丁名、别名搜索。
- 支持查看物种基础信息、详细内容、图片和浏览量。

### 2. 用户与权限

- 支持用户注册、登录和当前用户信息获取。
- 使用 Bearer Token 进行接口鉴权。
- 用户角色分为 `user`、`editor`、`admin`。
- 普通用户主要使用浏览、收藏和投稿功能。
- 编辑和管理员可以维护科属物种数据、审核投稿。

### 3. 收藏功能

- 登录用户可以收藏感兴趣的蛇类物种。
- 收藏表对 `user_id` 和 `species_id` 做唯一约束，避免重复收藏。
- 收藏列表会关联返回物种详情，方便前端直接展示。

### 4. 投稿与审核

- 用户可以提交新物种，也可以对已有物种发起纠错。
- 投稿状态包括 `pending`、`approved`、`rejected`。
- 审核通过后，后端会把投稿数据写入正式物种表、详情表和图片表。
- 审核拒绝时会记录审核意见。

### 5. 智能问答

- 主后端提供 `/chat` 接口。
- 使用 OpenAI SDK 兼容方式调用 DeepSeek 服务。
- 后端通过 SSE 流式返回回答内容，前端可以边生成边展示。
- 系统提示词限定 AI 以“蛇类专家”的身份回答，尽量保持回答客观、科学。

### 6. 图像识别

- 独立识别服务接收用户上传图片。
- 使用 BioCLIP 2 作为视觉特征提取模型。
- 加载本地训练得到的蛇类分类头权重。
- 推理时返回 Top-K 候选物种及置信度。

### 7. 图片资源管理

- 图片服务负责本地图片上传、导入和 URL 映射。
- 前端和主业务后端只保存图片 URL，不直接把图片二进制写入数据库。

## 三、系统架构

```text
Vue 3 前端 (:5173)
  |
  |-- 主业务后端 FastAPI (:8002)
  |     |-- 用户认证
  |     |-- 科 / 属 / 物种管理
  |     |-- 搜索与筛选
  |     |-- 收藏
  |     |-- 投稿审核
  |     |-- DeepSeek 流式问答
  |     `-- PostgreSQL 数据库
  |
  |-- 图像识别服务 FastAPI (:8000)
  |     `-- BioCLIP 2 + 本地分类头
  |
  `-- 图片服务 (:8003)
        `-- 本地图片上传、导入和访问
```

这种拆分方式的好处是：

- 主后端只负责稳定的业务数据和权限流程。
- 图像识别模型独立部署，避免大模型推理影响普通接口响应。
- 图片服务独立处理文件资源，数据库只保存结构化信息和图片地址。
- 前端可以按功能调用不同服务，便于开发调试和后续扩展。

## 四、技术栈

### 前端

- Vue 3：构建单页应用。
- Vite：开发和构建工具。
- TypeScript：提升前端代码可维护性。
- Vue Router：页面路由。
- Pinia：状态管理。
- Axios：HTTP 请求封装。

### 主业务后端

- FastAPI：构建 REST API，支持自动生成接口文档。
- SQLAlchemy Async：异步数据库访问。
- PostgreSQL：保存科属物种、用户、收藏、投稿等结构化数据。
- Pydantic：请求和响应数据校验。
- bcrypt：用户密码哈希。
- 自定义 JWT：实现登录态和角色鉴权。

### AI 与识别

- DeepSeek：用于蛇类知识问答。
- OpenAI SDK 兼容接口：统一调用大模型服务。
- PyTorch：模型推理框架。
- OpenCLIP / BioCLIP 2：提取生物图像特征。

## 六、数据库设计

主后端围绕蛇类百科设计了以下核心表：

| 表名 | 作用 |
| --- | --- |
| `families` | 蛇类“科”信息 |
| `genera` | 蛇类“属”信息，关联 `families` |
| `species` | 物种基础信息，关联 `genera` |
| `species_contents` | 物种详细百科内容 |
| `species_images` | 物种图片 URL 与说明 |
| `users` | 用户账号、角色、状态 |
| `user_favorites` | 用户收藏关系 |
| `species_submissions` | 用户投稿和审核记录 |

核心关系可以这样讲：

```text
families 1 --- n genera 1 --- n species
species  1 --- 1 species_contents
species  1 --- n species_images
users    1 --- n user_favorites n --- 1 species
users    1 --- n species_submissions
```

设计特点：

- 科、属、种分层保存，符合生物分类学结构。
- 物种基础信息和详细内容分表保存，避免列表接口返回过重。
- 图片只保存 URL，方便接入本地图片服务或后续对象存储。
- 收藏表使用唯一约束防止同一用户重复收藏同一物种。
- 投稿表保留审核状态、审核人、审核意见和创建物种 ID，便于追踪数据来源。

## 八、运行方式

### 1. 准备数据库

需要提前安装 PostgreSQL，并创建数据库：

```sql
CREATE DATABASE snake_db;
```

### 2. 配置后端环境变量

在 `backend/.env` 中配置：

```env
DATABASE_URL=postgresql+asyncpg://postgres:password@localhost:5432/snake_db
DEEPSEEK_API_KEY=your_deepseek_api_key
AUTH_SECRET_KEY=replace_with_a_strong_secret
SQL_ECHO=false
ACCESS_TOKEN_EXPIRE_MINUTES=10080
CORS_ORIGINS=http://127.0.0.1:5173,http://localhost:5173
```

说明：

- `DATABASE_URL` 是必填项，没有它后端会直接启动失败。
- `DEEPSEEK_API_KEY` 用于 `/chat` 智能问答接口。
- `AUTH_SECRET_KEY` 用于签发 Token，正式环境不能使用默认值。

### 3. 安装主后端依赖

当前后端目录没有固定依赖清单，可根据代码依赖安装：

```powershell
cd backend
pip install fastapi uvicorn sqlalchemy asyncpg python-dotenv bcrypt pydantic openai
```

### 4. 启动主业务后端

```powershell
cd backend
python main.py
```

默认地址：

```text
http://127.0.0.1:8002
```

接口文档地址：


启动时后端会根据 SQLAlchemy 模型自动创建数据表，并补充投稿表所需字段。


默认地址：

## 十、老师常问问题与回答

### 1. 为什么使用前后端分离？

前后端分离可以让页面展示和业务接口独立开发。前端只关心用户交互，后端只关心数据、权限和业务规则。这样后续如果要换移动端、小程序或者管理后台，也可以复用同一套后端接口。

### 2. 为什么要把图像识别服务单独拆出来？

图像识别依赖 PyTorch、OpenCLIP 和模型权重，启动慢、资源占用高。把它从主业务后端拆开，可以避免模型推理影响普通接口，例如登录、搜索和收藏。这样也方便后续把识别服务部署到有 GPU 的机器上。

### 3. 为什么数据库按科、属、种分表？

蛇类数据天然符合生物分类层级。如果把科、属、种都写在一个表里，会产生大量重复字段，也不方便筛选。分表后可以通过外键表达分类关系，数据结构更规范，查询和维护也更清晰。

### 4. 为什么物种详情要单独放 `species_contents`？

列表页通常只需要基础信息，如果每次都返回大段百科正文，会增加接口体积和数据库读取压力。把详情内容分表后，列表接口轻量，详情页按需加载，更符合实际业务访问模式。

### 5. 权限是怎么控制的？

系统登录后会返回 Bearer Token。后端解析 Token 后获取用户身份和角色。普通用户只能操作自己的收藏和投稿，编辑与管理员可以维护分类数据和审核投稿，管理员还可以管理用户。

### 6. 投稿审核为什么不直接写入正式物种表？

如果用户提交的数据直接入库，可能导致错误信息污染百科数据。因此先进入 `species_submissions` 投稿表，由编辑或管理员审核。审核通过后再写入正式表，审核拒绝则保留原因，保证数据质量可控。

### 7. AI 问答如何实现流式输出？

后端 `/chat` 接口返回 `text/event-stream`，通过 SSE 分段发送模型输出。前端接收到数据后可以逐步渲染，因此用户看到的是边生成边显示，而不是等完整回答生成后一次性返回。

### 8. 图像识别的基本流程是什么？

用户上传图片后，识别服务先用 PIL 读取图片，再用 BioCLIP 2 的预处理方式转换成模型输入。模型提取图像特征后进入本地训练的分类头，最后通过 softmax 得到各类别概率，返回置信度最高的候选物种。

### 9. 系统有什么创新点？

创新点主要体现在集成能力上：传统图鉴、图像识别、智能问答和用户共建不是分散功能，而是围绕蛇类知识库形成一个完整系统。用户可以查、可以识别、可以问，也可以补充和纠错。

### 10. 系统还有什么不足？

可以客观回答：

- 当前后端还缺少完整自动化测试。
- Python 依赖还没有整理成 `requirements.txt`。
- AI 问答目前主要依赖通用大模型，后续可以进一步接入本地知识库检索增强。
- 图像识别准确率还可以通过更多数据和更充分训练继续提升。
- 部署方面还可以补充 Docker Compose，一键启动多个服务。

## 十一、可以强调的技术亮点

- 使用 FastAPI 自动生成接口文档，方便联调和展示。
- 使用 SQLAlchemy Async 支持异步数据库访问。
- 使用 PostgreSQL 的 JSONB 和 ARRAY 保存别名、测量数据和投稿图片等半结构化信息。
- 使用角色权限控制区分普通用户、编辑和管理员。
- 投稿审核机制让用户贡献内容不会直接污染正式数据。
- AI 问答采用 SSE 流式响应，交互体验更接近真实智能助手。
- 图像识别服务独立部署，符合模型服务和业务服务解耦的工程思路。

## 十三、一分钟答辩稿

本项目是一个蛇类图鉴与智能识别系统，主要面向蛇类知识查询、图片识别、智能问答和内容共建场景。系统采用前后端分离架构，前端使用 Vue 3，主后端使用 FastAPI 和 PostgreSQL，图像识别服务使用 BioCLIP 2 和 PyTorch，智能问答接入 DeepSeek。

在业务上，系统支持蛇类科、属、种三级分类浏览，用户可以搜索物种、查看详情、收藏物种，也可以提交新物种或纠错信息。投稿不会直接进入正式数据，而是先进入审核流程，由编辑或管理员审核通过后再写入物种表、详情表和图片表。这样既支持用户共建，也保证数据质量。

在 AI 能力上，系统包含两部分：一部分是图像识别，用户上传蛇类图片后，模型返回候选物种和置信度；另一部分是智能问答，后端通过 SSE 流式返回大模型回答。整体上，项目把传统百科系统、图像识别和智能问答结合起来，形成了一个完整的蛇类知识服务平台。

## 十四、三分钟答辩稿

我的项目是蛇类图鉴与智能识别系统，目标是把蛇类百科查询、图片识别、智能问答和用户内容共建整合到一个平台中。系统不是单纯展示静态页面，而是有完整的用户体系、权限体系、数据维护流程和 AI 能力。

整体架构采用前后端分离。前端使用 Vue 3 和 Vite，负责图鉴页面、物种详情、收藏、投稿、审核、AI 问答和图片识别页面。主业务后端使用 FastAPI，负责用户认证、科属物种接口、搜索、收藏、投稿审核和问答接口。数据库使用 PostgreSQL，数据表按照蛇类生物分类结构设计，包括科表、属表、物种表、详情表、图片表、用户表、收藏表和投稿表。图像识别服务单独拆分出来，使用 PyTorch 和 BioCLIP 2，这样可以避免模型推理影响普通业务接口。

数据库设计上，科、属、种是层级关系，`families` 一对多关联 `genera`，`genera` 一对多关联 `species`。物种详情和图片单独分表，这样列表查询可以保持轻量，详情页再按需加载大段内容和图片。用户收藏表通过唯一约束避免重复收藏。投稿表保存投稿状态、审核人、审核意见和最终创建的物种 ID，保证用户贡献的数据可追踪、可审核。

权限方面，系统登录后返回 Bearer Token。后端解析 Token 后判断用户身份和角色。普通用户可以浏览、收藏、投稿，只能操作自己的数据；编辑和管理员可以审核投稿、维护科属物种；管理员还可以管理用户。这样可以避免普通用户直接修改正式知识库。

AI 功能分为两个部分。智能问答由后端 `/chat` 接口接入 DeepSeek，并通过 SSE 流式返回内容。图像识别由独立服务完成，用户上传图片后，服务用 BioCLIP 2 提取图像特征，再通过本地训练的分类头输出候选物种和置信度。后续还可以把识别结果和百科详情进一步打通，让用户从识别结果直接跳到物种页面。

这个项目的特点是把传统图鉴、AI 识别、智能问答和用户共建结合起来，形成了一个比较完整的蛇类知识服务闭环。后续可以继续完善自动化测试、依赖管理、Docker 部署和 RAG 检索增强，让系统更接近可部署的实际应用。
